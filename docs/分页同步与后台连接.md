# 分页同步与后台连接

适用于 SomaLoop 2 SDK 0.2.1 / build 43。本页介绍 0.2.1 新增入口；软件检查结果见随包 `release-report.json`，设备与手机后台验收另行记录。

## 按页保存历史

Swift 使用 `synchronizeHistory(_:options:onPage:)`；Kotlin 使用带 `onPage` 参数的 `syncHistoryRecords`。旧聚合入口继续可用。

```swift
let summary = try await client.synchronizeHistory(.temperature,
    options: HistorySyncOptions(checkpoint: savedCheckpoint,
        maximumPages: 20, useDeviceAnchor: true, maximumDurationSeconds: 8)
) { page in
    // 在宿主的同一事务中保存 page.records 和 page.checkpoint。
}
// 已使用回调入库时，不再重复写入 summary.records。
```

每次回调只有该页的新记录和累计 checkpoint。SDK 按顺序等待回调完成；保存失败会抛出，不再发送下一页。回调期间历史操作保持独占，不从回调重入读取、测量或其他设备命令。网络上传建议使用独立队列，避免阻塞 BLE 持久化。

`maximumDurationSeconds` 是页边界软预算，包含读取与保存时间，不是任意时刻的硬中止。新入口触及页数／时间预算时返回 `complete=false`、`interruption=nil`，并设置 `diagnostics.budgetExhausted=true`。实际传输中断仍通过 `interruption` 返回。两端 `maximumRecords` 均按本次收到的原始记录数计数，包含重复；超限返回 `queueOverflow`。旧聚合入口保留页预算 `queueOverflow` 行为。

部分读取、取消或中断不推进设备停止锚点；下次从旧锚点重读并去重。首次全量应在前台给予足够时间，反复使用极短预算会重复读相同前缀。不要任意截短 `seenFingerprints`；累计指纹与逐页序列化的成本应一并观测。

## 设备停止锚点

`profile.historyAnchorSupport(kind)` 分别返回调用支持、证据和原因。沿用 build 42 的范围兼容策略：有效四字节 BCD 固件 ≥0.0.8.8 的 steps、sleep、heartRate、hrv、temperature、ppi、spo2、sleepActivity 可显式使用 checkpoint 锚点，不以日期限制调用；其他类别完整读取并本地过滤。低于最低版本或无效版本不支持。

精确 `00000808-260604` 沿用已有设备证据；精确 `00010208-261016` 标记 `0128StaticHandlerParity`，仅有静态处理器一致性证据。其他准入版本／日期标记 `inheritedProtocolCompatibility`，代表继承已发布调用策略，未逐一实测或静态核验。后两类均标记 `exactCalendarOverlapPhysicalValidationPending`；兼容调用不等于物理验证，0128 本轮实体增量对照仍待完成。

锚点按设备日历精确相等停止，命中记录包含在结果中；它不是任意 `since` 或跨连接分页游标。仅完整且无中断的读取推进到第二新的不同完整日历，保留重叠。宿主仍应定期显式 `useDeviceAnchor=false` 全量对账，以覆盖同日历修订等边界。`since` 本身仅执行本地过滤。

## iOS 已绑定设备的恢复连接

```swift
try await client.setConnectionRecoveryTarget(
    id: savedIdentity.connectionID,
    expectedMAC: savedIdentity.hardwareAddress)
// 退出账号／解绑时先撤销；如需断开 ready 链路，再调用 disconnect()。
try await client.setConnectionRecoveryTarget(id: nil, expectedMAC: nil)
```

宿主按账号保存之前已经验证的 peripheral UUID 和 MAC，不能凭设备名称猜测。SDK 对同目标 ready 配置保持幂等；断连、蓝牙可用及状态恢复事件可再次发起连接。等待回到范围的系统 pending connect 不套用前台 20 秒截止；链路建立后的服务／通知订阅仍有超时边界，通知、MAC 与固件验证和读钟尝试之后才报告 ready。此恢复入口不自动校时或写设备配置。

显式扫描、连接、测量等操作可撤销 pending 恢复，随后按各自前提执行。采集会话、OTA 和恢复监督器优先占有客户端。`disconnect()`、`shutdown()` 撤销恢复意图；仅设置 nil 不会断开已经 ready 的链路。

宿主配置 `bluetooth-central`、稳定 restoration identifier，在恢复启动时重建客户端、恢复当前账号目标并订阅事件。iOS 决定后台唤醒与执行时间；用户强制退出后不能保证自动恢复。锁屏、离开返回、系统恢复和整夜表现须使用最终 App 真机验证。Android 本次提供分页／锚点 API，后台服务及生命周期由宿主负责。

新增 Kotlin data-class 字段后请重新编译宿主及其依赖；保留原 Java options 构造入口不代表任意预编译 Kotlin 字节码都可直接替换。
