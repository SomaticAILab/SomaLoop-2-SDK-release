# 实验性历史清除

**历史清除是不可逆的实验性功能，尚未完成两款支持固件的真机验收。** 当前文档将其标为实验性；运行时接口保持兼容，仍使用 `prepareHistoryErasure` 和显式 `confirm=true`，没有额外的 `allowExperimental` 参数或开关。能力快照可能仍显示 `compatibleCandidate`，这不代表删除效果已验收。

## 范围

当前支持固件版本为 0.0.7.9 和 0.0.8.8。调用方必须明确选择历史类型，没有默认“全部删除”：

| 类型 | 内容 |
| --- | --- |
| `steps` | 步数详情 |
| `sleep` | 睡眠记录 |
| `heartRate` | 连续心率 |
| `singleHeartRate` | 单次心率 |
| `hrv` | HRV 历史 |
| `sport` | 运动历史 |
| `temperature` | 温度历史 |
| `ppi` | PPI 历史 |
| `spo2` | 血氧历史 |

不支持按日期删除。`activity`、`sleepActivity`、闹钟和诊断历史不在此范围。清除 `sleep` 不保证清除 `sleepActivity`；所选类型读回为空也不能写成“整机数据已清空”。本接口不是恢复出厂，不保证清除设置、配对、密钥或账号访问权限。

## 准备与确认

连接必须就绪且空闲，没有待续页历史传输。宿主先完成需要保留的数据同步，向操作者展示所选设备与类型，得到明确的不可逆操作确认后再执行。

```swift
let preparation = try await client.prepareHistoryErasure(kinds: [.heartRate, .sleep])
// 宿主显示设备、类型和风险，得到用户确认后，在有效期内继续。
let report = try await client.eraseHistory(preparation, confirm: true)
```

```kotlin
val preparation = client.prepareHistoryErasure(listOf(HistoryKind.heartRate, HistoryKind.sleep))
// 宿主得到明确确认后继续。
val report = client.eraseHistory(preparation, confirm = true)
```

Java 先调用 `prepareHistoryErasure(kinds, Callback<HistoryErasurePreparation>)`，确认后调用 `eraseHistory(preparation, true, Callback<HistoryErasureReport>)`。不要把确认值写入自动连接或后台定时任务。

准备阶段不发送设备命令。凭证绑定当前客户端、连接、设备身份和所选类型，30 秒内有效，只能使用一次；新准备、断连、重连或关闭会使旧凭证失效。等待确认过久应重新准备并重新展示，不能把凭证持久化为以后自动执行的任务。

执行时每类请求至多尝试一次，写入异常停止后续删除，不自动重发。之后重新连接、核对设备身份并完整读回所选类型。取消、断连或中途失败**不回滚**已执行请求；多类型清除不是原子事务，新连接也不是固件内部删除完成的保证。

## 判断报告

`HistoryErasureReport` 包含设备身份、开始/结束时间（Unix 秒）、逐类 `results`、`freshConnectionVerified`、`checkpointResetRequired`、`interruption` 和派生的 `readbackEmpty`。

| 逐类字段 | 含义 |
| --- | --- |
| `commandAttempted` | 请求已交给传输层，设备可能已收到，即使写调用后来报错 |
| `transportWriteCompleted` | 传输写调用完成，不是设备删除完成证明 |
| `verification` | `notAttempted`、`empty`、`recordsPresent` 或 `unknown` |
| `recordCount` | 新连接读回实际见到的记录数 |
| `readComplete` | 本次验证读取完整且未中断 |
| `interruption` | 该类型的读取/操作中断原因 |

`empty` 仅表示完整新读中未见记录；`recordsPresent` 可能包括删除后新产生的数据；`unknown` 表示缺少充分验证结果；`notAttempted` 表示尚未发出该类删除请求。

只有新连接身份核对通过、所有所选类型均完整读回为空且没有中断，`readbackEmpty` 才为 true。它不证明永久物理擦除、其他类型为空或设备已停止产生新数据。

任一请求可能发出后，`checkpointResetRequired` 为 true。宿主须持久化报告，并废弃相关旧 checkpoint、续页游标和绑定周期同步进度，后续从新读取开始。取消或回调中断后还要查询 `lastHistoryErasureReport`；Swift/Kotlin 为客户端属性，Java 为回调方法。该报告仅在当前客户端内存中，进程退出不会自动恢复或重发删除。

## 解绑与验收

清除与服务器解绑不是同一个事务。宿主应限制本次交接期间的新认领，核对设备与绑定周期；出现新绑定、过期或离线旧任务时取消旧清除，不能在下次连接时盲目执行。清除后由应用停止自己的自动重连。删除历史不会撤销旧手机的设备访问能力。

两款固件须分别验证：清除前有数据、明确选择的类型完成删除、新连接完整空读、随后产生的新记录可正常读取；同时对照时钟、设置、配对和未请求类型。手机、取消、断连及部分失败也要保留结果。在这些实测完成前，产品应保持实验性标识，不把软件测试通过宣传为清除效果已验收。
