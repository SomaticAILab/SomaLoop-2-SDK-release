# 实验性历史清除

历史清除是不可逆的实验性功能，默认关闭。准备和执行均须显式传 `allowExperimental=true`，执行另需 `confirm=true`。能力状态为 `experimental`，快照 `available=false`、`requiresExperimentalOptIn=true`；旧签名或 `allowExperimental=false` 会在发帧前返回 `unverifiedCapability`。

## 范围

仅固件 0.0.8.8 提供该实验性入口。更高固件可接入和读取，清除入口仍受此范围限制。调用方须明确选择历史类型：

| 类型 | 内容 |
| --- | --- |
| `steps` | 步数详情 |
| `sleep` | 睡眠记录 |
| `heartRate` | 连续心率 |
| `singleHeartRate` | 单次心率 |
| `hrv` | HRV 历史 |
| `sport` | 运动历史 |
| `temperature` | 温度历史 |
| `ppi` | PPI 历史 |
| `spo2` | 血氧历史 |

不支持按日期删除或默认全部删除。`activity`、`sleepActivity`、闹钟和诊断历史不在清除请求范围；`sleep` 的读回结果仅适用于 `sleep`。本接口不提供恢复出厂，配对和账号访问权限由应用另行处理。

## 准备与确认

连接必须就绪且空闲，没有待续页历史传输。宿主先完成需要保留的数据同步，向操作者展示所选设备与类型，得到明确的不可逆操作确认后再执行。

```swift
let preparation = try await client.prepareHistoryErasure(kinds: [.heartRate, .sleep], allowExperimental: true)
// 宿主显示设备、类型和风险，得到用户确认后，在有效期内继续。
let report = try await client.eraseHistory(preparation, confirm: true, allowExperimental: true)
```

```kotlin
val preparation = client.prepareHistoryErasure(listOf(HistoryKind.heartRate, HistoryKind.sleep), allowExperimental = true)
// 宿主得到明确确认后继续。
val report = client.eraseHistory(preparation, confirm = true, allowExperimental = true)
```

Java 先调用 `prepareHistoryErasure(kinds, true, Callback<HistoryErasurePreparation>)`，确认后调用 `eraseHistory(preparation, true, true, Callback<HistoryErasureReport>)`；后者布尔值依次为 `confirm` 和 `allowExperimental`。每次清除都须由操作者明确发起。读取接口的 `allowUntested` 不能启用清除；实验开关保留固件、类型、连接身份和凭证校验。

准备阶段不发送设备命令。凭证绑定当前客户端、连接、设备身份和所选类型，30 秒内有效，只能使用一次；新准备、断连、重连或关闭会使旧凭证失效。确认超时后须重新准备并展示所选范围，不持久化凭证或安排自动执行。

每类删除请求至多尝试一次，不自动重发。所有请求正常写入后，SDK 重新连接、核对设备身份并完整读回所选类型。写入异常、取消或断连会停止后续操作，并关闭本次连接；已经发送的请求不回滚，多类型清除不是原子事务。

## 判断报告

`HistoryErasureReport` 包含设备身份、开始/结束时间（Unix 秒）、逐类 `results`、`freshConnectionVerified`、`checkpointResetRequired`、`interruption` 和派生的 `readbackEmpty`。

| 逐类字段 | 含义 |
| --- | --- |
| `commandAttempted` | 请求已交给传输层，设备可能已收到，即使写调用后来报错 |
| `transportWriteCompleted` | 传输写调用完成；所选类型的结果查看新连接读回 |
| `verification` | `notAttempted`、`empty`、`recordsPresent` 或 `unknown` |
| `recordCount` | 新连接读回实际见到的记录数 |
| `readComplete` | 本次读回完整且未中断 |
| `interruption` | 该类型的读取/操作中断原因 |

`empty` 表示完整读回中未见记录；`recordsPresent` 表示读回有记录，其中可能包括删除后新产生的数据；`unknown` 表示读回结果未确定；`notAttempted` 表示未发出该类删除请求。

新连接身份核对通过、所有所选请求写入完成、各类型均完整读回为空且没有中断时，`readbackEmpty` 为 true。它只描述本次所选类型的读回结果；设备仍可继续产生新记录。

任一请求可能发出后，`checkpointResetRequired` 为 true。宿主须保存报告，废弃相关旧 checkpoint、续页游标和绑定周期同步进度，后续从新读取开始。取消或回调中断后还要查询 `lastHistoryErasureReport`；Swift/Kotlin 为客户端属性，Java 为回调方法。该报告仅保存在当前客户端内存中，进程退出后不会自动恢复或重发删除。

## 与应用解绑配合

清除和服务器解绑由应用分别处理。宿主须核对设备与绑定周期；出现新绑定、过期或离线旧任务时取消旧清除。清除后由应用停止自己的自动重连，并另行处理旧手机的设备访问权限。
