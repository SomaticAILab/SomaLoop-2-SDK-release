# 远程依赖与版本锁定

以下入口分发 **SomaLoop 2 SDK 0.1.16 / build 33** 的原有二进制；不包含 0.2.0 源码候选。构建指纹为 `5ca9eadaa9cc6b078895bdf17a9d7e0e1abb36e328c6cf9d3c0094f76e14ea1e`。

## Swift Package Manager

在 Xcode 的 Add Package Dependencies 输入仓库 URL，Dependency Rule 选择 Commit，填入根目录 `distribution-update.json` 的 `rootPackageRevision` 完整值；或在 Package.swift 中使用：

```swift
.package(
    url: "https://github.com/SomaticAILab/SomaLoop-2-SDK-release.git",
    revision: "<替换为 distribution-update.json 的 rootPackageRevision>"
)
```

添加 `SomaLoopSDK` 产品，需要研究接口时添加 `SomaLoopExperimental`。提交 App 的 `Package.resolved`，升级时明确更换 revision 并核对对应版本、构建号与验证报告。不要依赖 main 的浮动最新状态，也不要对这个 revision 使用 `from: "0.1.16"`：本入口以提交锁定，未增加语义版本 tag。

仓库根清单引用仓库内已发布 XCFramework。SPM 自行通过 Git 取回，无需手工拷包；当前使用 `binaryTarget(path:)` 随远程包解析，而非独立 ZIP 的 `binaryTarget(url:checksum:)`。这会下载发布仓库，下载体积大于单独二进制 ZIP。iOS 15+；需要完整 Xcode 编译、签名和安装 App。

已实测全新消费者的 `swift package resolve` 成功，Package.resolved 指向上述提交；37 个 iOS Package 文件与 v0.1.16-build33 的校验和一致。本次未重新执行 iOS 编译或手机安装；原构建报告仍只对应原制品。

## Maven

不需要手工复制本地 repository，Gradle 可直接读取固定发布 tag 的仓库目录：

```kotlin
// settings.gradle.kts 的 dependencyResolutionManagement.repositories
exclusiveContent {
    forRepository {
        maven {
            name = "SomaLoopRelease"
            url = uri("https://raw.githubusercontent.com/SomaticAILab/SomaLoop-2-SDK-release/v0.1.16-build33/android/repository")
        }
    }
    filter { includeGroup("com.somaticai.somaloop") }
}
google()
mavenCentral()

// app/build.gradle.kts
implementation("com.somaticai.somaloop:sdk:0.1.16")
implementation("com.somaticai.somaloop:experimental:0.1.16") // 可选
```

SDK 坐标固定版本，仓库 URL 固定 tag；不要使用 `+`、SNAPSHOT 或 main URL。启用 Gradle dependency locking 并提交 lockfile，可进一步启用 dependency verification。公共仓库不需要凭据，不把 GitHub token 放进工程。运行依赖仍由 Google/Maven Central 解析，若离线接入则使用完整下载包内的 repository。
