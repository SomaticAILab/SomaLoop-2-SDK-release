# 功能支持范围

适用于 SomaLoop 2 SDK 0.2.1 / build 43。SDK 默认接入有效 BCD 固件版本 ≥0.0.8.8，不设默认上限；无效版本和低于最低版本的设备返回 `unsupportedProfile`。应用可在此范围内收窄准入策略。

连接后调用 `capabilitySnapshot()`，按具体功能和历史类型检查 `state`、`available` 与 `requiresExperimentalOptIn`。C 表示 `compatibleCandidate`，E 表示 `experimental`，U 表示 `untested`；实验开关不能放行 `unsupported` 或低于最低版本的设备。

| 功能 | 范围与调用条件 |
| --- | --- |
| 设备信息、设置读取、主动测量、纯 PPG、原始 ECG、马达节拍 | 固件 ≥0.0.8.8，C；连接就绪并空闲时调用 |
| 15 类历史（包含 alarms）及独立闹钟设置读取 | 固件 ≥0.0.8.8，C；默认无需读取开关 |
| 联合 PPG＋MEMS 采集 | 固件 ≥0.0.8.8，C；使用 `paired` 模式 |
| 主动佩戴检查 | 固件 ≥0.0.8.8；观察 1–10 秒，停止规则按固件分别处理 |
| 新固件设备 HRV 结果、心率状态历史 | 仅 `00010208-261016`；实验性结果／历史，后者需显式启用；有效 HRV 与非空新历史尚未验收 |
| 恢复出厂 | 0.0.8.8 / 260604，C；无实验开关，需一次性确认和充电唤醒；见[恢复出厂](恢复出厂.md) |
| 设备校时 | 固件 ≥0.0.8.8，C；使用 `synchronizeClock`，写入后检查回读结果 |
| 独立 ACC | 固件 ≥0.0.8.8，C；主库 `startCapture(accOnly)` 支持持久会话 |
| 历史清除 | 固件 ≥0.0.8.8，E；准备与执行分别显式实验启用，执行另需确认 |
| 独立实时诊断、通用设置写入、`capture24Hours` 能力 | U，不列为常规可用功能 |

15 类历史为 `activity`、`steps`、`sleep`、`heartRate`、`singleHeartRate`、`hrv`、`alarms`、`sleepDebug`、`systemEvents`、`sport`、`temperature`、`ppi`、`spo2`、`powerDebug` 和 `sleepActivity`。闹钟使用 `readSettings(.alarms)` / `readSettings(SettingKind.alarms)`；只有完整列表才返回设置快照，部分结果使用历史批次读取。

## 读取与操作

历史批次保存实际返回的记录，并通过 `complete`、`interruption` 和 `continuationAvailable` 描述本次传输。设备时间、原始计数和睡眠设备标签按[数据与时间语义](数据与时间语义.md)处理。独立实时诊断与本地 `exportDiagnostics` 摘要导出是不同入口。

采集和马达共用客户端操作互斥。应用须提供停止入口、转发前后台状态，并保存待关闭会话；恢复时核对原设备 MAC、固件和日期。马达是普通可用功能，无需实验开关。调用和导出说明见[采集与马达节拍](采集与马达节拍.md)。

历史清除不可逆，准备凭证绑定当前客户端、连接、设备身份和类型，30 秒内有效且仅使用一次。取消、断连或失败不回滚已发送的请求。调用、读回结果和同步进度处理见[实验性历史清除](历史清除.md)。

平台调用方式见 [iOS 接入](iOS接入.md)与 [Android / Java 接入](Android接入.md)，错误处理见 [API 与错误码](API与错误码.md)。

## 本版本的软件验证与设备观察

随包 `release-report.json` 记录实际平台测试和二进制消费者检查，`build-identity.json` 与 `SHA256SUMS` 标识本包。软件检查、Mac 蓝牙实测、手机和长期验收分别记录，不相互替代。

2026-11-05 已完成 0128 HTTPS 固件服务及双端 SDK 的清单查询、完整 ZIP 下载、哈希和包解析验证。Mac 系统代理下的大响应停滞通过显式进程级网络配置完成直连验证，宿主按自身网络策略接入。手机实机刷写另待验收。

以下是 0.2.0 / build 40、单只 0128 / 261016 设备的 Mac 实测结论；仅发布汇总，不包含原始个人记录：

- 自然佩戴窗口检查设备日历 08–19 点的 12 个每小时 `:12` 检查点，之后均有非零连续心率记录，未复现持续停记。仍有零槽和记录头间隔；0128 首槽时间规则未确认，不能换算精确缺样时长，也不能据此宣布旧 0088 根因已修复。
- 分别 5 分钟联合采集和纯 PPG 的操作对照均出现对应窗口的连续心率历史缺口；停止后恢复，延迟回读未补齐。历史读取完整结束不代表采集中仍生成常规记录；本次完整历史读取未复现持续约 3 分钟停记。
- 一轮约 21 分钟联合采集完成两次续租和一次主动断连恢复、确认停止与导出。其独立 PPG 仍有序号缺口，后续短测也有自然链路中断和恢复读钟超时，不能承诺连续采集无断连。
- 最后纯 PPG 轮完成约 300 秒，302 包、15100 点，无序号缺口；随后联合轮约 175 秒链路中断，未完成计划的 5 分钟，独立 PPG 估计缺 4 包。会话最终均已确认停止。
- 联合帧存在 50／51 点及 `Time=999/1000/1001`。跨流逐值匹配支持共同值序列和不同分包；主机接收存在突发，尚不能确认 50、51.2 或 52 Hz 的物理采样时钟、逐点时间和 PPG／ACC 同步。时间契约保持 `unverified`（`timing_verified=false`）。
- 未佩戴时固件也曾报告 `worn`。此字段只表示固件接触提示，不作为实际佩戴事实；没有近期心率也不能推定未佩戴。

此前 build 36 的 Mac OTA 升级、build 37 的佩戴对照及 build 38 的独立 ACC 停止失败保留原构建身份：OTA 未验证生产 HTTPS 供包、手机和断电恢复；0128 独立 ACC 停止 ACK 未确认；实验 HRV 有效结果与非空新心率状态历史尚未验收。

手机 BLE／后台、双设备、整夜与长期共存、ECG 完整性和物理单位、充电码／电压标定、被动接触码及固件 RRI 字段语义仍需单独验证。公开接口和诊断补齐不代表上述固件问题全部解决。
