# 功能支持范围

适用于 SomaLoop 2 SDK 0.1.11 / build 27。SDK 默认接入有效 BCD 固件版本 ≥0.0.8.8，不设默认上限；无效版本和低于最低版本的设备返回 `unsupportedProfile`。应用可在此范围内收窄准入策略。

连接后调用 `capabilitySnapshot()`，按具体功能和历史类型检查 `state`、`available` 与 `requiresExperimentalOptIn`。C 表示 `compatibleCandidate`，E 表示 `experimental`，U 表示 `untested`；实验开关不能放行 `unsupported` 或低于最低版本的设备。

| 功能 | 范围与调用条件 |
| --- | --- |
| 设备信息、设置读取、主动测量、纯 PPG、原始 ECG、马达节拍 | 固件 ≥0.0.8.8，C；连接就绪并空闲时调用 |
| 15 类历史及闹钟读取 | 固件 ≥0.0.8.8，C；默认无需读取开关 |
| 联合 PPG＋MEMS 采集 | 仅 0.0.8.8、固件日期 `260604`，C；使用 `paired` 模式 |
| 设备校时 | 仅 0.0.8.8、固件日期 `260604`，C；使用 `synchronizeClock` |
| 独立 ACC | `00000808-260604` 为 C；主库 `startCapture(accOnly)` 支持持久会话。其他准入固件为 E，可经研究模块显式实验入口使用 |
| 历史清除 | 仅 0.0.8.8，E；准备与执行分别显式实验启用，执行另需确认 |
| 独立实时诊断、通用设置写入、`capture24Hours` 能力 | U，不列为常规可用功能 |

15 类历史为 `activity`、`steps`、`sleep`、`heartRate`、`singleHeartRate`、`hrv`、`alarms`、`sleepDebug`、`systemEvents`、`sport`、`temperature`、`ppi`、`spo2`、`powerDebug` 和 `sleepActivity`。闹钟使用 `readSettings(.alarms)` / `readSettings(SettingKind.alarms)`；只有完整列表才返回设置快照，部分结果使用历史批次读取。

## 读取与操作

历史批次保存实际返回的记录，并通过 `complete`、`interruption` 和 `continuationAvailable` 描述本次传输。设备时间、原始计数和睡眠设备标签按[数据与时间语义](数据与时间语义.md)处理。独立实时诊断与本地 `exportDiagnostics` 摘要导出是不同入口。

采集和马达共用客户端操作互斥。应用须提供停止入口、转发前后台状态，并保存待关闭会话；恢复时核对原设备 MAC、固件和日期。马达是普通可用功能，无需实验开关。调用和导出说明见[采集与马达节拍](采集与马达节拍.md)。

历史清除不可逆，准备凭证绑定当前客户端、连接、设备身份和类型，30 秒内有效且仅使用一次。取消、断连或失败不回滚已发送的请求。调用、读回结果和同步进度处理见[实验性历史清除](历史清除.md)。

平台调用方式见 [iOS 接入](iOS接入.md)与 [Android / Java 接入](Android接入.md)，错误处理见 [API 与错误码](API与错误码.md)。
