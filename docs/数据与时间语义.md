# 数据与时间语义

应用使用 SDK 已解码的字段，并保留质量标记和原始记录引用。SDK 返回模型与应用上传格式分别设计，上传时由应用明确映射字段。

可从[历史读取](#历史读取)、[数值与缺失](#数值单位与缺失)、[实时帧](#实时帧与接收记录)、[时间](#时间)、[增量同步](#增量同步与-clockepoch)、[JSON 编码](#json-时间约定)或[测试构造器](#应用单元测试)开始。本文的“宿主”指接入方 App；“生成固件”指记录产生时运行的固件；“保存日历”指设备记录里的日期字段，可能没有时区或完整日期。

## 历史读取

SDK 接受有效 BCD 固件版本 0.0.8.8 及以上，不设版本上限；15 类历史读取的能力状态为 `compatibleCandidate`。`readHistoryBatch` 返回 `HistoryBatch`：

| 字段 | 含义 |
| --- | --- |
| `kind` | 本次读取的历史类型 |
| `records` | 当前页完整解码的 `DecodedPacket` 集合；不是通知集合 |
| `notificationCount` | 历史通知数量，不能当记录数或分钟数 |
| `complete` | 本次读取已看到完整结束条件，仍须同时检查中断 |
| `continuationAvailable` | 可以在当前连接、同类型读取中请求下一页 |
| `interruption` | 可选错误；失败前的记录仍可能有效 |
| `clock`、`clockUnavailableReason` | 取回时的时钟快照或不可用原因 |

先保存记录，再检查 `complete && interruption == nil/null`。未完成且允许续页时继续读取；跨断连、换类型或重新开始后不能复用旧 `continuation`。日汇总与闹钟不支持该续页方式。`syncHistory` 会先交付含部分记录的批次，再报告中断。

Swift 用 `try batch.typedRecords` 转为 `[HistoryRecord]`；Kotlin 用 `batch.records.map { HistoryDecoder.decode(it) }`。`synchronizeHistory` / `syncHistoryRecords` 直接返回类型化记录及 checkpoint、页数、去重数、过滤数和完整性信息。checkpoint 必须与本次记录在宿主的同一持久化事务中保存，避免崩溃后跳过未落盘数据。

`HistoryRecord` 中 `recordID` 是传输内编号；数据库主键需另行设计，并包含设备身份和绑定/时钟周期。`fingerprint` 是内容指纹，完全相同内容可能被合并。`rawHex` 保留原始记录，与 `fingerprint` 一并原样保存。分享导出前由宿主处理设备身份和个人数据。

`complete` 表示本次协议传输完整结束。定期完整对账用于找回设备已保存的迟到或修订记录；未保存的采样无法通过重读恢复。

下面保存一次温度读取的原始批次、类型化记录和样本。将代码放在应用的 `async` 调用路径中，`pageFile` 为本批次独立的可写文件 URL；跨次去重及 checkpoint 使用后文的增量同步入口。

```swift
struct SavedTemperaturePage: Codable {
    let batch: HistoryBatch
    let records: [HistoryRecord]
    let samples: [HistorySample]
}
func saveTemperaturePage(client: SomaLoopClient, pageFile: URL,
                         timeContract: HistoryTimeContract? = nil) async throws -> HistoryBatch {
    let batch = try await client.readHistoryBatch(.temperature)
    let records = try batch.typedRecords
    let samples = try records.flatMap { try $0.samples(field: "temperatureRaw", contract: timeContract) }
    let saved = SavedTemperaturePage(batch: batch, records: records, samples: samples)
    try JSONCoding.encoder().encode(saved).write(to: pageFile, options: .atomic)
    return batch // 保存后再检查 complete、interruption 和 continuationAvailable。
}
```

默认不提供时间契约，样本保留原始索引且 `timestamp=nil`。只有已确认记录头是首样本时刻、间隔及记录生成时区时，才传 `HistoryTimeContract(headerMeaning: .firstSample, intervalSeconds: ..., utcOffsetMinutes: ..., sourceEvidence: ...)`；不能用手机当前时区或本次读钟结果补造这些条件。

## 数值、单位与缺失

`HistoryRecord.series` 是 `HistorySeries[]`，包含 `field`、`unit`、`slots`、可选 `intervalSeconds`、`timestampMeaning` 和 `sourceEvidence`。每个槽位保留 `index`、`rawValue`、可选 `value` 和 `quality`；`value` 是 SDK 按字段定义换算后的值。

| 数据 | 使用说明 |
| --- | --- |
| 心率 | `bpm`；零值可能保留为空槽位，不解释为零次心跳 |
| 步数 | 整数步数；零步数有效；汇总与分钟序列不能重复相加 |
| 步数和日汇总中的距离、热量 | 类型化值分别为 `km`、`kcal`；不要对已换算值再次缩放；运动记录的浮点字段另见下表 |
| 温度 | 类型化值为 `degC`；零或异常值结合质量处理，不能推定核心体温 |
| 血氧 | `percent`；保留质量标记与原值 |
| PPI | `ms`；保留终止位及其后的槽位，不能压缩后推算时间 |
| HRV、疲劳、压力估计 | 保留设备指标名称、单位与质量；不按名称套用其他指标定义 |
| 睡眠 | 时间解析器提供区间，适配器按支持固件输出设备阶段标签；不从通用原码序列自行推测 |
| 运动和诊断 | 部分字段尚无类型化业务解释，`series` 可能为空 |

`quality` 常见值为 `raw`、`zeroUnclassified`、`terminator`、`afterTerminator`、`unknownCode`。`qualityFlags` 可说明日历缺失、时间来源未确认或内容身份可能合并。空值、零、空数组与字段缺失含义不同；保留原位置，不先过滤空值再重排时间。

0.1.13/build29 新增 packet / history record 的 `measurements` 视图。以下字段仅在对应记录中存在；不适用或字段缺失返回 `nil/null`。这些接口目前属于本地开发候选，不能把既有发布包当作已包含新接口。

| 视图字段 | 有单位的输入 | 数值与质量 |
| --- | --- | --- |
| `skinTemperature` | 实时包、温度历史及温度设备信息 | 原整数 × 0.1，`degC`；零保留原值，`value=null`、`zeroUnclassified` |
| `distance` / `calories` | 实时包、步数或日汇总历史 | 原整数 × 0.01，分别为 `km` / `kcal`；零有效 |
| `steps` | 实时包、步数或日汇总历史 | 整数步数，`unit="steps"`；零有效 |
| 运动历史的 `distance` / `calories` | 已解码的浮点字段，物理单位待确认 | 有限值原样放入 `value/rawValue`，`unit=null`、`unitUnverified`；不自动当作 km/kcal |

运动浮点为 NaN 或无穷大时，`value/rawValue` 均为空，`quality=nonFinite`，原始字节仍由 packet / history record 保留。`raw` 仅表示按现有字段定义返回，不是测量准确性评级。已有心率/血氧用 `measurementValues`，已有历史序列继续用 `series`；新增视图不改写它们或原始 JSON 字段。

闹钟记录的 `alarmLabel` 返回 `DecodedText`。有效 UTF-8 为 `quality=decoded`；无效 UTF-8 返回 `text=null`、`quality=invalidUTF8`，不插入替换字符掩盖错误。原始 `textBytes` 和整条原文继续保留，空字符串也可以是有效解码结果。

HRV 记录中的 `heartRate` 为零时，该槽保留 `rawValue=0`、`value=nil/null` 和 `quality=zeroUnclassified`。同一记录中的 HRV、疲劳和压力指标分别读取各自的单位与质量。

## 实时帧与接收记录

0.1.13/build29 的 `SDKEvent.ppg(PPGRecord)` 和 `accRecord(ACCRecord)` 分别交付 PPG / 独立 ACC 帧及其原始接收记录；Android 对应 `SDKEvent.PPG` 和 `SDKEvent.ACCRecord`。PPG 事件在 PPG-only 及联合采集接收到独立 PPG 帧时产生，联合帧继续使用 `paired`。这些数据视图不证明采样覆盖或物理单位。

| 字段 | 使用方式 |
| --- | --- |
| `frame` | PPG 的 `sequence/bytesPerSample/values`，或 ACC 的 `sequence/samples/unknownTail/rawHex` |
| `receive.time` | 通知到达宿主的时间；Swift 内存为 `Date`，双端日志 JSON 为 Unix 毫秒 |
| `receive.uptime` / `background` | 接收时主机单调秒及 App 前后台状态 |
| `receive.fileID` / `fileRecord` | 对应 `raw-*.jsonl` 的文件和行；结合会话 ID 保存，不能跨会话单独作为唯一键 |
| `receive.hex` | 同一通知的原始内容，供追溯使用 |

持久采集中的事件使用实际落盘记录。独立 ACC 的 `accRecord` 与导出 `acc-frames.jsonl` 对应项的 `frame/receive` 一致，不需再与上一条 `raw` 事件配对；PPG 的接收引用指向原始日志，没有新增独立的 PPG 导出文件。接收时间不是逐点采样时间，序号也不能单独作为全局唯一键。

SDK 保留旧 `acc(ACCFrame)` / Android `ACC` 兼容事件，同一帧会同时发出旧事件和新事件。新接入方只用 `accRecord` / `ACCRecord` 保存或上传 ACC；`raw`、`packet`、`acc` 用于诊断或兼容显示，不再记成新的测量。联合采集也不要把 `ppg` 与 `paired` 中同一批样本重复累计。

```swift
// 放在已建立的事件订阅中；保存到 App 自己的队列，避免阻塞接收。
switch event {
case .ppg(let record):
    print(record.frame.values.count, record.receive.time)
case .accRecord(let record):
    let encoded = try JSONCoding.encoder().encode(record)
    print(encoded.count, record.receive.fileID as Any, record.receive.fileRecord as Any)
default: break
}
```

### 包分类与扫描候选

`DecodedPacket.kind` 是 SDK 提供的 `PacketKind`，取值为 `history/realtime/ppg/acc/ecg/control/debug/unknown`；历史记录另有可空 `historyKind`。控制回复与历史记录分别分类，App 按类型分支，无须解释 `layout` 或命令字。

`DiscoveredDevice.discoveryKind` 为 `candidate` 或 `unknown`；`discoveryEvidence` 说明 `advertisedName` / `advertisedService` 依据，`advertisedServiceUUIDs` 可为空。广播不足或系统找回的设备可以保持 `unknown`，不要因此丢弃。候选表示值得连接识别，是否支持某功能仍由连接后的设备身份、固件和能力快照决定。

let samples = (0..<6).map { _ in MEMSSample(x: 1, y: 2, z: 3) }

Kotlin / Java 使用 `SDKTestValues.packet`、`acc`、`ecg` 和 `ppg`。例如 Kotlin `SDKTestValues.ppg(0, List(25) { 100L })` 使用默认四字节样本；三字节样本可显式指定 `bytesPerSample=3`。Swift 的波形构造器及 Android 的对应辅助函数检查序号、样本数和取值范围。合成 packet / ACC / ECG 的 `rawHex` 为空，不具备设备原文来源；它们不能绕过 `HistoryRecord` 对原文、字段和内容身份的校验，也不能作为真机验收证据。

## PPI 计算的 RMSSD（SDK 正式算法）

使用 `PPIHRV.fromBatch` 从一次完整 PPI 历史读取生成独立的 RMSSD 输出。SDK 重组同一保存日历下的完整分组，按下面的标准规则筛选间期，以原本相邻且两端均保留的差分计算 RMSSD。有效结果的 `rmssdMilliseconds` 单位为 `ms`，可映射到应用的 `hrv_rmssd`，用于同来源、同窗口规则的个人 HRV 基线、恢复分和偏低提醒。分数及提醒阈值由应用定义；SDK 不提供恢复或压力评分公式。

```swift
let results = try PPIHRV.fromBatch(ppiBatch)
for result in results {
    if let rmssd = result.rmssdMilliseconds {
        // 保存到 hrv_rmssd，同时保存 result 的来源、策略和质量。
        print(rmssd, result.quality)
    } else {
        // 保存缺失原因，本次不更新基线、恢复分或偏低提醒。
        print(result.unavailableReason as Any)
    }
}
```

```kotlin
val results = PPIHRV.fromBatch(ppiBatch)
for (result in results) {
    val rmssd = result.rmssdMilliseconds
    if (rmssd != null) {
        println("hrv_rmssd=$rmssd; quality=${result.quality}")
    } else {
        println(result.unavailableReason)
    }
    val stored = result.toJson() // 包含显式 null，不以 0 代替缺失。
}
```

Java 使用 `PPIHRV.fromBatch(ppiBatch)` 和 `result.getRmssdMilliseconds()`，返回可空 `Double`，先判空再拆箱。Swift 用 `JSONEncoder`，Android 用 `result.toJson()`；两端 JSON 均保留显式 `rmssdMilliseconds: null` 和原因。

已有连续、有序且单位为毫秒的间期时，可直接使用 Swift `try PPIHRV.calculate(intervalsMilliseconds: intervals)` 或 Kotlin / Java `PPIHRV.calculate(intervals)`。已有类型化历史记录时使用 `fromHistory`，仅传同一设备、同次读取、同一保存日历的完整分组；默认仅在完整集合上识别 0 或 1 起始编号，也可显式传入 `groupIndexBase`。不要跨设备或跨次读取拼接；分页数据应先完成读取和组装，不能只将最后一页当作完整数据。`fromBatch` 拒绝未结束、中断或仍可续页的批次；空的完整批次返回空列表。

SomaLoop 2 SDK 的正式 HRV 算法为 **`ppi-rmssd`**，通过 `PPIHRV` 输出 RMSSD（ms）。默认 `PPIHRVPolicy` 的计算规则如下：

1. 完整组装一个原始 PPI 窗口。原始间期须为有限的毫秒数，范围为 **300–2000 ms（含边界）**；缺失或越界返回 null。历史末组的连续零终止区不计入间期。
2. 取全部原始间期的算术平均值 `mean`，一次性保留 **`0.70 × mean ≤ PPI ≤ 1.05 × mean`** 的点。参考均值只计算一次，不按筛选结果反复更新，也不使用设备心率作参考。
3. 筛后至少保留 **35 个间期**；不足时返回 null。
4. 仅对原始序列中相邻、且两端都保留的点计算差分。令这些差分为 `d`，数量为 `m`，则 **`RMSSD = sqrt(sum(d²) / m)`**。若 `m=0`，返回 null。删除点两侧不拼接，不插值。

计算参数为 `minimumIntervalCount`（筛后数量）、`minimumMeanRatio`、`maximumMeanRatio` 和原始间期范围。

| 结果 | 下游处理 |
| --- | --- |
| `rmssdMilliseconds` 非空，`quality=screenedPPI` | 直接保存到 `hrv_rmssd`，用于个人基线、恢复分和偏低提醒；同时保存来源、算法、策略和质量。0 是有效数值 |
| `missingIntervals` | 没有间期，保存 null |
| `insufficientRetainedIntervals` | 筛后少于策略要求的数量，保存 null；通过数量字段查看筛前、筛后数量 |
| `noOriginalAdjacentPairs` | 筛后数量足够，但没有原本相邻且两端都保留的点，保存 null |
| `invalidInterval` | 原始输入含缺失、非有限值或范围外间期，整个窗口返回 null |
| `incompleteRead` / `incompleteGroups` / `duplicateGroup` | 读取或分组不完整，返回 null；完成读取并核对完整集合后再算 |
| 其他分组、日历、记录或终止位错误 | 返回 null 和具体原因，保留原始记录以便检查 |

每个结果同时输出以下计算信息（Swift `JSONEncoder` / Android `toJson()` 均包含这些字段）：

| 字段 | 含义 |
| --- | --- |
| `intervalCount` | 筛选前的原始间期数；未能完成历史组装时为 0 |
| `retainedIntervalCount` / `rejectedIntervalCount` | 筛选后保留 / 剔除的数量；尚未执行筛选时为 null |
| `successiveDifferenceCount` | 筛后仍然原本相邻的点对数，即公式中的 `m`；即使因数量不足返回 null，也保留此计数；尚未筛选时为 0 |
| `referenceMeanMilliseconds` | 全部原始间期的算术均值；尚未筛选时为 null |
| `lowerBoundMilliseconds` / `upperBoundMilliseconds` | 本窗口实际筛选上下界；尚未筛选时为 null |
| `source` / `algorithm` / `policy` | `ppi` / `ppi-rmssd` / 本次完整计算参数 |
| `deviceSaveTime` / `sourceFingerprints` | 设备保存日历 / 来源记录指纹 |

`observedDurationSeconds` 是筛选前全部间期之和（秒）。保存日历不作为测量窗口起点，也不凭时间接近将独立的 HRV 与 PPI 记录拼成同一次测量。

使用同一来源和计算参数建立个人基线；历史数据可从原始 PPI 按上述规则重算。升级 SDK 后重新编译应用。

### 设备原始 HRV

历史协议中的 `hrv` 字段按设备原文保留，`HistorySeries.unit` 为 `vendorUnverified`（它不是 quality 枚举）。应用的 HRV 数值统一使用上述正式算法返回的 `PPIHRVResult.rmssdMilliseconds`，原始字段单独归档。

`hrvMillisecondEvidence` 是原始字段的宿主元数据，不参与 SDK HRV 计算。

## 时间

设备日历不自带时区。`DeviceCalendar` 的日期精度可能只有年月日，不能自动补午夜。历史 `utcOffsetMinutes` 指**记录生成时**设备日历的 UTC 偏移，范围为 −840 至 840；UTC+08:00 为 480。手机当前时区、读取时固件或现在的钟差不能代替历史生成条件。

| 时间字段 | 单位与含义 |
| --- | --- |
| `HistorySample.timestamp` | Unix 秒，可为空；无依据时不造逐点时间 |
| 睡眠区间 `startUnixMilliseconds` / `endUnixMilliseconds` | Unix 毫秒；结束边界不包含在本区间内 |
| `ClockSnapshot.offsetSeconds` | 设备时间减宿主时间，单位秒；不是历史统一修正量 |
| `ClockSnapshot.hasLargeOffsetWarning` | 已知钟差的绝对值达到一小时；时区未提供、钟差未知时为 false，仍需检查 offset 是否为空 |
| `utcOffsetMinutes` | 日历时区偏移分钟，不是设备快慢误差 |
| ECG、清除报告 `startedAt` / `endedAt` | Unix 秒，描述宿主操作边界 |
| 会话日志 JSON `time` | UTC Unix 毫秒；Swift 内存中是 `Date` |
| 日志 `uptime` | 单调时钟秒，仅用于同一主机时间基准的间隔 |

`HistoryTimeContract` 由调用方提供记录头含义、采样间隔、生成时区和时间来源。默认 `record.samples(...)` 保留样本位置而不生成绝对时间。读取时的时钟快照不用于统一平移历史记录；定期完整对账用于发现较早记录的修订。

## 睡眠与连续心率

对已支持的生成固件 0.0.8.8、构建日期 2026-06-04，内建睡眠规则以记录头为开始，每个有效睡眠码生成一分钟区间。`SleepTimelineResolver.resolve` 返回保留原顺序的区间；`SomaContractAdapter.historyWithDeviceTiming` 对 `sleep` 记录进一步生成设备的 `deep`、`light`、`rem`、`awake` 标签。调用时提供真实的生成固件和显式时区；不把当前连接信息无条件套到旧历史。

未知生成固件、无时区或非法日历时保留未知和原因。区间覆盖时长包含清醒，不能直接命名为总睡眠时长；深睡、浅睡和 REM 可分别累计，缺口与重叠单独处理。`sleep` 与 `sleepActivity` 可能表达重叠内容，不能合并为两份睡眠相加。SDK 不按使用者自述入睡/起床时间剪裁设备记录。

通用数据层的 `unknownCode` 或 `sleepDurationUnverified` 与专门时间解析结果分别保存。保留有效原码、索引和设备阶段标签，首槽按现有规则处理，不删除首分钟或平移时间轴。

同一受支持生成固件的连续心率规则按每槽五秒展开；其他生成条件保留原始槽位。`SomaContractAdapter` 返回适配对象、来源信息和拒绝原因，网络上传由宿主处理。睡眠活动的适配默认保留原始记录；需要其时间轴时由宿主单独解析并保存，避免与睡眠区间重复累计。

### 可选上传格式适配

只有接收端采用对应格式时才使用 `SomaContractAdapter`；它不负责网络上传，也不是读取历史的前提。`hrv_rmssd` 是应用字段映射示例，应用可采用自己的字段名。

`SomaContractAdapter.contractVersion="v1"`、`defaultContractRevision` 和 `supportedContractRevisions` 标明适配契约。旧入口使用 `.legacyV1`；接收端支持新版时，调用 `historyForContract(..., contractRevision: .diagnosticHistoryV1, ...)` 显式选择。该修订可适配 `sleepDebug` / `systemEvents` 原始记录，不生成派生指标；`powerDebug` 缺少完整日历时仍保留本地并返回 `calendarPrecisionInsufficient`。`.partialCalendarHistoryV1` 为可选的部分日历映射；显式选择后可将合法 powerDebug 月日时分原样上传为八位 `MMddHHmm`、`precision="minute_no_year"`，不补当前年份或秒，不生成绝对时间。服务端的年份解析与 SDK 原始日历分别处理，上传成功仍须核对实际接收结果。历史读取能力与上传契约分别判断。

## 设置与主动测量

`SettingSnapshot` 含 `kind`、`fields` 与原文。闹钟快照汇总完整记录列表、各条原文、记录数和通知数；列表不完整会抛错。步数目标由 App／服务端维护，不属于SDK的设备设置项。字段缺失不能当作设置关闭，也不应通过回写默认值“修复”。

主动测量返回解码结果集合，只保存实际测量数据。启动/停止确认不是测量值；空集合、超时、取消与实际零值分开处理。HRV 入口中的设备指标不能仅凭名称解释为某个标准 HRV 算法。

SDK 提供读取辅助：`DeviceInfoResult.batteryReading` 返回 `percentage` 与 `rawHex`；`percentage` 含 `rawValue`、可选 `value`、`unit="percent"` 和 `quality`。电量零为有效值，超过百分比名义范围则保留原值并将换算值留空。`readBattery()` 的 `readAt` 为实际通知接收的主机 Unix 秒，与 `battery` 事件 `observedAt` 相同。已有 `DeviceInfoResult.batteryReading` 静态转换没有接收上下文，仍为 null；不使用转换时刻代替。

`DecodedPacket.measurementValues` 转换实时测量包中的 `heartRate`（名义 `bpm`）和 `spo2`（名义 `percent`），并保留 `rawHex`。零为 `zeroUnclassified`，超出血氧名义百分比范围为 `outsideNominalRange`，对应 `value` 留空。控制回复没有该视图；该视图不生成标准 HRV 指标或逐值时间。Java 使用 `ApiViews.batteryReading(result)` / `ApiViews.measurementValues(packet)`；旧字段保留，readAt 新增为可空接收时间。

## 操作与日常历史共存

SDK 对同一客户端的操作实行互斥。日常历史按设备实际保存的记录返回；应用保存各项操作的开始、结束与停止结果，并保留历史原时间轴、空槽和缺口。采集开始事件不表示日常心率历史已暂停，全量重读用于补齐设备已保存的内容。

应用可按下表保存宿主操作窗口。各项操作都可能占用固件资源，但 SDK 尚不能确认具体设备是否暂停日常心率、何时恢复或是否补写；操作成功也不保证日常历史持续生成。

| 操作 | 应保存的窗口及结果 |
| --- | --- |
| PPG-only / paired / accOnly 采集 | 启动调用、首个实际数据、软重启/断连、停止调用及 `stopConfirmed` / `cleanupPending`；两路 PPG 分别计数 |
| 有限 ECG / 通用研究流 | 启动、实际接收范围、停止与中断；ECG 的接收窗口不等于生理采样覆盖 |
| 主动测量 | 启动、实际测量通知、停止及取消/超时；停止应答不表示日常心率已经恢复 |
| 历史读取 | 首次请求、每页边界、结束标记和中断；读取本身也作为待分析的操作窗口 |

对照时先保存完整历史，保留无操作的观察窗，再保存采集/测量后的立即读取及延迟复读。按记录内容指纹比较迟到记录和修订，而非只比较总条数；“完整结束”仅指传输完成。使用受支持的记录生成固件及真实时区解析时间，读钟偏差单独记录，不能统一平移历史来填补缺口。

同窗 HRV 的心率槽为零时，继续保留 `zeroUnclassified`，HRV 值及其未确认单位单独保存。时间重叠或心率零槽不足以将整条 HRV 自动标为无效；SDK 不生成“历史已暂停”事实事件，也不补造未保存的心率。

## 原始 ECG

可选模块的 `recordECG(seconds)` 录制有限时长的原始 ECG，时长 30 至 300 秒，默认 60。`rawECG` 的能力状态为 `compatibleCandidate`。

| 字段 | Swift | Kotlin / Java |
| --- | --- | --- |
| 时间与时长 | `startedAt`、`endedAt`、`requestedSeconds` | 同名 |
| 数据集合 | `packets: [DecodedPacket]`；SDK另提供类型化 `frames` 视图 | `frames: List<ECGFrame>` |
| 数据内容 | packet 的 `layout` 为 `ecg_181` / `ecg_244`，`fields` 中读取 `values`、`sequence`、`unknownTail`；类型化帧同名字段 | 每帧 `values`、`sequence`、`unknownTail`、`rawHex` |
| 终止状态 | `stopConfirmed`、可选 `interruption` | 同名 |
| 接收摘要 | `sampleCount`、`receptionSummary` | 同名扩展属性；Java `ApiViews.ecgReceptionSummary(recording)` |
| 接收时序 | 可选 `receptionTiming`；摘要同样提供 | 同名；使用本机单调接收时间，不是逐样本时间 |
| 采样率 | `receptionSummary.sampleRateHz` / `expectedSampleCount` 未知 | 录制对象 `sampleRateHz` 与摘要中的采样率/期望数当前未知 |

跨端存储需显式映射两端对象。样本为未校准的原始计数，保留其名义值，不换算为电压；操作开始/结束时间也不作为逐样本时间。

Swift `frames`、双端 `sampleCount` / `receptionSummary` 是辅助视图，原 `packets` / `frames` 字段保持。0.1.8 的录制对象新增可选 `receptionTiming`，旧 JSON 缺少该字段仍可读取；没有实际时序观测时为空。摘要包含 `frameCount`、`sampleCount`、`sequenceDiscontinuityCount` 和 `completeness="unknown"`。序号不连续次数包括重复；使用时与样本数分别保存，不将其换算为缺失样本数。

`receptionTiming` 的观测窗从首条 ECG 启动命令前开始，在停止清理前结束，包含启动应答前收到的帧，排除停止清理中的通知。

| 时序字段 | 含义 |
| --- | --- |
| `observationDurationSeconds` | 宿主单调观测窗长度 |
| `receivedFrameCount` | 进入该时序观测的帧数 |
| `firstFrameOffsetSeconds` / `lastFrameOffsetSeconds` | 首/末帧相对观测窗开始的接收偏移；无帧时为空 |
| `maximumInterFrameGapSeconds` | 相邻接收帧的最大间隔；不足两帧时为空 |
| `leadingSilenceSeconds` / `trailingSilenceSeconds` | 窗首/窗尾未收到帧的时间；无帧时均为整个观测窗 |

用这些字段区分“只收到少量帧”和“接收遍布操作窗口”。它们不证明设备何时采样、数据是否缓存、帧内样本覆盖或医学信号质量。没有已确认采样率时，SDK 仍不设置通用 `insufficientData` 阈值；连续序号、`interruption=nil/null` 和停止应答均不能把 `completeness` 升级为完整。

```swift
let summary = recording.receptionSummary
print(summary.sampleCount, summary.sequenceDiscontinuityCount)
for frame in recording.frames { print(frame.sequence, frame.values.count) }
// 原 packets 视图的样本位于 packet.fields["values"]。
```

`sampleRateHz` 和 `expectedSampleCount` 当前为空；接收样本数除以请求时长不作为采样率。样本数、帧数、序号不连续次数与停止状态分别保存。

`interruption` 非空仍可能有可保存的部分数据。前置条件失败、启动失败或取消也可能抛错，不保证所有错误都写在对象内。**分别检查 `stopConfirmed` 与 `interruption`**；双端在无其他中断且停止未确认时标记 `stopUnconfirmed`。保留未确认事实，不因方法返回就认为物理采集结束。

可选模块的通用 `start` / `stop` 与有限录制分别使用。Android 通用 `start` 没有宿主截止定时器，宿主须在 `finally` 调用 `stop()`；有限时长的 ECG 使用 `recordECG`。

## 电量、接触状态与独立 ACC

`startCapture(accOnly)` 使用持久会话，只开启 ACC；默认一天、最多七天，支持同身份恢复及导出。`ACCFrame` 含六组有符号 XYZ 原始计数，不提供已校准单位或样本时间。

`readBattery` 是空闲时的单条读取；`chargingStateRaw` 和 `voltage.rawValue` 分别保留 SDK 解码的原始充电码和无符号电压值。充电状态、缩放及单位未经确认，枚举为 `unknown`，物理值和单位为 `null`。采集中返回 `busy`，只有收到实际电量通知时才发电量事件，不保证固件主动推送。

`readWearState` 在 `00000808-260604` 上短暂打开 PPG / 调试，观察时长为 1–10 秒，默认 5 秒，另计写入和关闭超时。它返回固件接触状态，不留采集目录；已有操作返回 `busy`，无信号返回 `unknown`，关闭失败返回 `stopUnconfirmed` 并断连。

采集中的 `skinContact` 事件解析完整的 `TOUCH/touch_flag` 接触报告；被动接触状态事件保留 `rawValue`、接收时刻和 `state=unknown`，不映射成佩戴或未佩戴。`touchValue` 阈值仍未知。未接触时提示调整佩戴或停止 PPG，避免无数据重启循环；新增类型化接口不改变这些语义。

## 增量同步与 clockEpoch

`currentClockEpoch` 在识别设备后返回有效时钟纪元。没有 SDK 校时记录时为 `unspecified`；本 SDK 每次已记录的时钟写入尝试（包括写入失败但可能影响设备的情况）会生成新纪元，并按设备持久保存。保留 storageRoot、重启后重新识别设备即可恢复。它不监测其他应用对设备时钟的修改。

Swift 可省略 `synchronizeHistory` 的 `clockEpoch`；Kotlin `HistorySyncOptions()` 默认采用客户端有效纪元，Java 从 `currentClockEpoch()` 获取。checkpoint 同时绑定设备、历史类型和纪元；已知纪元变化时旧 checkpoint 会被拒绝，应用应保留旧记录、移除旧 checkpoint 并重新完整对账，不能将旧记录直接改成新纪元。

以下用单文件原子替换示范记录与 checkpoint 同时落盘。实际数据库应在同一事务中提交去重后的记录和新 checkpoint：

```swift
struct SavedHistory: Codable {
    var batches: [HistorySyncResult] // 每批保留其设备、纪元和完整性信息
    var checkpoint: HistoryCheckpoint
}
let previous = try? JSONCoding.decoder().decode(SavedHistory.self, from: Data(contentsOf: historyFile))
let epoch = await client.currentClockEpoch // 已连接识别
let checkpoint = previous?.checkpoint.clockEpoch == epoch ? previous?.checkpoint : nil
let result = try await client.synchronizeHistory(.temperature, checkpoint: checkpoint)
let saved = SavedHistory(batches: (previous?.batches ?? []) + [result], checkpoint: result.checkpoint)
try JSONCoding.encoder().encode(saved).write(to: historyFile, options: .atomic)
// 若 complete=false，保留已收记录并按 interruption 安排下次对账；不要覆盖为空集合。
```

historyFile 是应用为当前设备和历史类型提供的持久文件 URL。上例的 batches 是追加日志，数据库使用设备+纪元+指纹去重，不能直接把数组长度当新增测量数。切换设备或历史类型时使用独立存储键，示例不负责替应用迁移这些键。Kotlin 对应 `client.syncHistoryRecords(kind, HistorySyncOptions(checkpoint = checkpoint))`，结果连同已有记录在数据库事务内保存；Java 使用相同 options 的 Callback 入口。

## JSON 时间约定

Swift `JournalRecord.time` 和 `SessionManifest.createdAt/plannedEndAt/endedAt` 固定编解码为 **Unix 毫秒数**，普通 `JSONEncoder/JSONDecoder` 与 `JSONCoding` 得到相同语义，不受 dateEncodingStrategy/dateDecodingStrategy 改变；旧 SDK 自身保存的毫秒文件可继续读取。推荐 `JSONCoding.encoder()/decoder()` 保存 SDK 模型。旧应用若自行保存过 2001 纪元秒，应根据其已知旧格式显式迁移，SDK 不猜测数字单位。

PPIHRVResult 没有 Date 字段，普通 JSONEncoder 可直接编码；null 表示缺失，RMSSD=0 则是有效数值。Android 日志和会话日期同样用 Unix 毫秒数。

## 新模型与质量值

| 模型 / 字段 | 定义 |
| --- | --- |
| WearState.state | worn / notWorn / unknown；表示固件接触状态 |
| WearState.source | touch / touch_flag / 0x86 / timeout |
| WearState.rawValue | 可空的设备状态原文，不作为校准后的信号质量 |
| WearState.observedAt | 主机 Unix 秒；不是设备采样时间 |
| WearState.firmwareTime / touchValue | 可空设备原文，不解释 touchValue 阈值 |
| ACCFrame.samples | 顺序六组 XYZ，signed int16 原始计数，单位/采样率未提供 |
| ACCFrame.sequence / unknownTail / rawHex | 序号（0–255）、尾部十六进制字符串、完整十六进制原文；不生成逐样本时间 |
| BatteryReading.percentage | rawValue、可空 value、percent 单位和 quality；0% 有效，>100 的 value=null |
| BatteryReading.readAt | 可空主机 Unix 秒；readBattery 和事件包含接收时间，静态转换为空 |
| BatteryReading.chargingState / chargingStateRaw | unknown / 原始码；不可按非零判充电 |
| BatteryReading.voltage | rawValue 为无符号原值；value、unit 未知 |

质量值按模型解释，不存在跨模型通用的 quality 枚举：HistorySlot 使用 `raw/zeroUnclassified/terminator/afterTerminator/unknownCode`；ReportedValue 另有 `outsideNominalRange`；PPIHRVResult 使用 `screenedPPI/unavailable`；NumericReading 另有 `unitUnverified/nonFinite`。`vendorUnverified` 是设备原始 HRV 序列的 unit。

`HistoryRecord.qualityFlags` 的当前取值如下；它们解释记录的已知限制，应用应保存并容忍新增值，不应把存在任意 flag 一律当成丢弃整条记录的理由。

| flag | 含义 |
| --- | --- |
| `contentIdentityMayConflateIdenticalRecords` | 内容相同的记录可能得到相同指纹 |
| `zeroMeaningUnconfirmed` | 序列中存在含义未确认的零槽 |
| `nonzeroAfterTerminator` | PPI 终止位之后还有非零原值 |
| `typedPayloadUnverified` | 尚未提供完整的通用 `series` 解释；不否定另有的字段视图 |
| `calendarUnavailable` | 无有效设备日历 |
| `sleepDurationUnverified` | 通用数据层未认定睡眠时长；另看专门时间解析结果 |
| `headerIsSaveTime` | PPI 记录头是保存时刻，不能当逐点起始时间 |
| `sampleOriginUnverified` | 通用数据层未确认记录头与首样本的关系 |
