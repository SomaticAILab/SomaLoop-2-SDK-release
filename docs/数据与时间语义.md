# 数据与时间语义

应用使用 SDK 已解码的字段，并保留质量标记和原始记录引用。SDK 返回模型与应用上传格式分别设计，上传时由应用明确映射字段。

## 历史读取

SDK 接受有效 BCD 固件版本 0.0.8.8 及以上，不设版本上限；15 类历史读取的能力状态为 `compatibleCandidate`。`readHistoryBatch` 返回 `HistoryBatch`：

| 字段 | 含义 |
| --- | --- |
| `kind` | 本次读取的历史类型 |
| `records` | 当前页完整解码的 `DecodedPacket` 集合；不是通知集合 |
| `notificationCount` | 历史通知数量，不能当记录数或分钟数 |
| `complete` | 本次读取已看到完整结束条件，仍须同时检查中断 |
| `continuationAvailable` | 可以在当前连接、同类型读取中请求下一页 |
| `interruption` | 可选错误；失败前的记录仍可能有效 |
| `clock`、`clockUnavailableReason` | 取回时的时钟快照或不可用原因 |

先保存记录，再检查 `complete && interruption == nil/null`。未完成且允许续页时继续读取；跨断连、换类型或重新开始后不能复用旧 `continuation`。日汇总与闹钟不支持该续页方式。`syncHistory` 会先交付含部分记录的批次，再报告中断。

Swift 用 `try batch.typedRecords` 转为 `[HistoryRecord]`；Kotlin 用 `batch.records.map { HistoryDecoder.decode(it) }`。`synchronizeHistory` / `syncHistoryRecords` 直接返回类型化记录及 checkpoint、页数、去重数、过滤数和完整性信息。checkpoint 必须与本次记录在宿主的同一持久化事务中保存，避免崩溃后跳过未落盘数据。

`HistoryRecord` 中 `recordID` 是传输内编号；数据库主键需另行设计，并包含设备身份和绑定/时钟周期。`fingerprint` 是内容指纹，完全相同内容可能被合并。`rawHex` 保留原始记录，与 `fingerprint` 一并原样保存。分享导出前由宿主处理设备身份和个人数据。

`complete` 表示本次协议传输完整结束。定期完整对账用于找回设备已保存的迟到或修订记录；未保存的采样无法通过重读恢复。

## 数值、单位与缺失

`HistoryRecord.series` 是 `HistorySeries[]`，包含 `field`、`unit`、`slots`、可选 `intervalSeconds`、`timestampMeaning` 和 `sourceEvidence`。每个槽位保留 `index`、`rawValue`、可选 `value` 和 `quality`；`value` 是 SDK 按字段定义换算后的值。

| 数据 | 使用说明 |
| --- | --- |
| 心率 | `bpm`；零值可能保留为空槽位，不解释为零次心跳 |
| 步数 | 整数步数；零步数有效；汇总与分钟序列不能重复相加 |
| 距离、热量 | 类型化值分别为 `km`、`kcal`；不要对已换算值再次缩放 |
| 温度 | 类型化值为 `degC`；零或异常值结合质量处理，不能推定核心体温 |
| 血氧 | `percent`；保留质量标记与原值 |
| PPI | `ms`；保留终止位及其后的槽位，不能压缩后推算时间 |
| HRV、疲劳、压力估计 | 保留设备指标名称、单位与质量；不按名称套用其他指标定义 |
| 睡眠 | 时间解析器提供区间，适配器按支持固件输出设备阶段标签；不从通用原码序列自行推测 |
| 运动和诊断 | 部分字段尚无类型化业务解释，`series` 可能为空 |

`quality` 常见值为 `raw`、`zeroUnclassified`、`terminator`、`afterTerminator`、`unknownCode`。`qualityFlags` 可说明日历缺失、时间来源未确认或内容身份可能合并。空值、零、空数组与字段缺失含义不同；保留原位置，不先过滤空值再重排时间。

HRV 记录中的 `heartRate` 为零时，该槽保留 `rawValue=0`、`value=nil/null` 和 `quality=zeroUnclassified`。同一记录中的 HRV、疲劳和压力指标分别读取各自的单位与质量。

设备历史 `hrv` 当前保留为 `vendorUnverified`，不能改标为 RMSSD、SDNN 或毫秒，也不能直接填入 `hrv_rmssd`、标准 HRV 基线、恢复分或偏低提醒。现有调查不支持将整列解释为标准 RMSSD；某批数值与自算结果相关，不能证明全部固件、计算窗口、质量处理和异常路径具有相同定义。`hrvMillisecondEvidence` 是调用方提交的依据说明，SDK 不会认证字符串的真实性；不得填写占位文字来绕过单位检查。

需要标准 RMSSD 时，应从单位、质量和窗口均明确的间期单独计算，记录算法及滤波规则，并与设备原始 HRV 分开保存。PPI 的保存时间不等于测量窗口起点，相近时间的记录不自动组成同一次测量；PPI 也不自动等同经过正常窦性筛选的 NN 间期。

## 时间

设备日历不自带时区。`DeviceCalendar` 的日期精度可能只有年月日，不能自动补午夜。历史 `utcOffsetMinutes` 指**记录生成时**设备日历的 UTC 偏移，范围为 −840 至 840；UTC+08:00 为 480。手机当前时区、读取时固件或现在的钟差不能代替历史生成条件。

| 时间字段 | 单位与含义 |
| --- | --- |
| `HistorySample.timestamp` | Unix 秒，可为空；无依据时不造逐点时间 |
| 睡眠区间 `startUnixMilliseconds` / `endUnixMilliseconds` | Unix 毫秒；结束边界不包含在本区间内 |
| `ClockSnapshot.offsetSeconds` | 设备时间减宿主时间，单位秒；不是历史统一修正量 |
| `ClockSnapshot.hasLargeOffsetWarning` | 已知钟差的绝对值达到一小时；时区未提供、钟差未知时为 false，仍需检查 offset 是否为空 |
| `utcOffsetMinutes` | 日历时区偏移分钟，不是设备快慢误差 |
| ECG、清除报告 `startedAt` / `endedAt` | Unix 秒，描述宿主操作边界 |
| 会话日志 JSON `time` | UTC Unix 毫秒；Swift 内存中是 `Date` |
| 日志 `uptime` | 单调时钟秒，仅用于同一主机时间基准的间隔 |

`HistoryTimeContract` 由调用方提供记录头含义、采样间隔、生成时区和时间来源。默认 `record.samples(...)` 保留样本位置而不生成绝对时间。读取时的时钟快照不用于统一平移历史记录；定期完整对账用于发现较早记录的修订。

## 睡眠与连续心率

对已支持的生成固件 0.0.8.8、构建日期 2026-06-04，内建睡眠规则以记录头为开始，每个有效睡眠码生成一分钟区间。`SleepTimelineResolver.resolve` 返回保留原顺序的区间；`SomaContractAdapter.historyWithDeviceTiming` 对 `sleep` 记录进一步生成设备的 `deep`、`light`、`rem`、`awake` 标签。调用时提供真实的生成固件和显式时区；不把当前连接信息无条件套到旧历史。

未知生成固件、无时区或非法日历时保留未知和原因。区间覆盖时长包含清醒，不能直接命名为总睡眠时长；深睡、浅睡和 REM 可分别累计，缺口与重叠单独处理。`sleep` 与 `sleepActivity` 可能表达重叠内容，不能合并为两份睡眠相加。SDK 不按使用者自述入睡/起床时间剪裁设备记录。

通用数据层的 `unknownCode` 或 `sleepDurationUnverified` 与专门时间解析结果分别保存。保留有效原码、索引和设备阶段标签，首槽按现有规则处理，不删除首分钟或平移时间轴。

同一受支持生成固件的连续心率规则按每槽五秒展开；其他生成条件保留原始槽位。`SomaContractAdapter` 返回适配对象、来源信息和拒绝原因，网络上传由宿主处理。睡眠活动的适配默认保留原始记录；需要其时间轴时由宿主单独解析并保存，避免与睡眠区间重复累计。

`SomaContractAdapter.contractVersion="v1"`、`defaultContractRevision` 和 `supportedContractRevisions` 标明适配契约。旧入口使用 `.legacyV1`；接收端支持新版时，调用 `historyForContract(..., contractRevision: .diagnosticHistoryV1, ...)` 显式选择。该修订可适配 `sleepDebug` / `systemEvents` 原始记录，不生成派生指标；`powerDebug` 缺少完整日历时仍保留本地并返回 `calendarPrecisionInsufficient`。0.1.8 新增 `.partialCalendarHistoryV1`，对应服务端修订 `5b6a08115fe491fbb79afc9a8c75f7e705715f44`；显式选择后可将合法 powerDebug 月日时分原样上传为八位 `MMddHHmm`、`precision="minute_no_year"`，不补当前年份或秒，不生成绝对时间。服务端的年份解析与 SDK 原始日历分别处理，上传成功仍须核对实际接收结果。历史读取能力与上传契约分别判断。

## 设置与主动测量

`SettingSnapshot` 含 `kind`、`fields` 与原文。闹钟快照汇总完整记录列表、各条原文、记录数和通知数；列表不完整会抛错。步数目标由 App／服务端维护，不属于SDK的设备设置项。字段缺失不能当作设置关闭，也不应通过回写默认值“修复”。

主动测量返回解码结果集合，只保存实际测量数据。启动/停止确认不是测量值；空集合、超时、取消与实际零值分开处理。HRV 入口中的设备指标不能仅凭名称解释为某个标准 HRV 算法。

SDK提供读取辅助：`DeviceInfoResult.batteryReading` 返回 `percentage` 与 `rawHex`；`percentage` 含 `rawValue`、可选 `value`、`unit="percent"` 和 `quality`。电量零为有效值，超过百分比名义范围则保留原值并将换算值留空。原返回对象没有读取时间，`readAt` 为未知；由 App 保存实际请求和接收时间，不能使用转换时刻代替。

`DecodedPacket.measurementValues` 转换实时测量包中的 `heartRate`（名义 `bpm`）和 `spo2`（名义 `percent`），并保留 `rawHex`。零为 `zeroUnclassified`，超出血氧名义百分比范围为 `outsideNominalRange`，对应 `value` 留空。控制回复没有该视图；该视图不生成标准 HRV 指标或逐值时间。Java 使用 `ApiViews.batteryReading(result)` / `ApiViews.measurementValues(packet)`；旧返回类型和序列化形状保持。

## 操作与日常历史共存

SDK 对同一客户端的操作实行互斥。日常历史按设备实际保存的记录返回；应用保存各项操作的开始、结束与停止结果，并保留历史原时间轴、空槽和缺口。采集开始事件不表示日常心率历史已暂停，全量重读用于补齐设备已保存的内容。

应用可按下表保存宿主操作窗口。各项操作都可能占用固件资源，但 SDK 尚不能确认具体设备是否暂停日常心率、何时恢复或是否补写；操作成功也不保证日常历史持续生成。

| 操作 | 应保存的窗口及结果 |
| --- | --- |
| PPG-only / paired / accOnly 采集 | 启动调用、首个实际数据、软重启/断连、停止调用及 `stopConfirmed` / `cleanupPending`；两路 PPG 分别计数 |
| 有限 ECG / 通用研究流 | 启动、实际接收范围、停止与中断；ECG 的接收窗口不等于生理采样覆盖 |
| 主动测量 | 启动、实际测量通知、停止及取消/超时；停止应答不表示日常心率已经恢复 |
| 历史读取 | 首次请求、每页边界、结束标记和中断；读取本身也作为待分析的操作窗口 |

对照时先保存完整历史，保留无操作的观察窗，再保存采集/测量后的立即读取及延迟复读。按记录内容指纹比较迟到记录和修订，而非只比较总条数；“完整结束”仅指传输完成。使用受支持的记录生成固件及真实时区解析时间，读钟偏差单独记录，不能统一平移历史来填补缺口。

同窗 HRV 的心率槽为零时，继续保留 `zeroUnclassified`，HRV 值及其未确认单位单独保存。时间重叠或心率零槽不足以将整条 HRV 自动标为无效；SDK 不生成“历史已暂停”事实事件，也不补造未保存的心率。

## 原始 ECG

可选模块的 `recordECG(seconds)` 录制有限时长的原始 ECG，时长 30 至 300 秒，默认 60。`rawECG` 的能力状态为 `compatibleCandidate`。

| 字段 | Swift | Kotlin / Java |
| --- | --- | --- |
| 时间与时长 | `startedAt`、`endedAt`、`requestedSeconds` | 同名 |
| 数据集合 | `packets: [DecodedPacket]`；SDK另提供类型化 `frames` 视图 | `frames: List<ECGFrame>` |
| 数据内容 | packet 的 `layout` 为 `ecg_181` / `ecg_244`，`fields` 中读取 `values`、`sequence`、`unknownTail`；类型化帧同名字段 | 每帧 `values`、`sequence`、`unknownTail`、`rawHex` |
| 终止状态 | `stopConfirmed`、可选 `interruption` | 同名 |
| 接收摘要 | `sampleCount`、`receptionSummary` | 同名扩展属性；Java `ApiViews.ecgReceptionSummary(recording)` |
| 接收时序 | 可选 `receptionTiming`；摘要同样提供 | 同名；使用本机单调接收时间，不是逐样本时间 |
| 采样率 | `receptionSummary.sampleRateHz` / `expectedSampleCount` 未知 | 录制对象 `sampleRateHz` 与摘要中的采样率/期望数当前未知 |

跨端存储需显式映射两端对象。样本为未校准的原始计数，保留其名义值，不换算为电压；操作开始/结束时间也不作为逐样本时间。

Swift `frames`、双端 `sampleCount` / `receptionSummary` 是辅助视图，原 `packets` / `frames` 字段保持。0.1.8 的录制对象新增可选 `receptionTiming`，旧 JSON 缺少该字段仍可读取；没有实际时序观测时为空。摘要包含 `frameCount`、`sampleCount`、`sequenceDiscontinuityCount` 和 `completeness="unknown"`。序号不连续次数包括重复；使用时与样本数分别保存，不将其换算为缺失样本数。

`receptionTiming` 的观测窗从首条 ECG 启动命令前开始，在停止清理前结束，包含启动应答前收到的帧，排除停止清理中的通知。

| 时序字段 | 含义 |
| --- | --- |
| `observationDurationSeconds` | 宿主单调观测窗长度 |
| `receivedFrameCount` | 进入该时序观测的帧数 |
| `firstFrameOffsetSeconds` / `lastFrameOffsetSeconds` | 首/末帧相对观测窗开始的接收偏移；无帧时为空 |
| `maximumInterFrameGapSeconds` | 相邻接收帧的最大间隔；不足两帧时为空 |
| `leadingSilenceSeconds` / `trailingSilenceSeconds` | 窗首/窗尾未收到帧的时间；无帧时均为整个观测窗 |

用这些字段区分“只收到少量帧”和“接收遍布操作窗口”。它们不证明设备何时采样、数据是否缓存、帧内样本覆盖或医学信号质量。没有已确认采样率时，SDK 仍不设置通用 `insufficientData` 阈值；连续序号、`interruption=nil/null` 和停止应答均不能把 `completeness` 升级为完整。

```swift
let summary = recording.receptionSummary
print(summary.sampleCount, summary.sequenceDiscontinuityCount)
for frame in recording.frames { print(frame.sequence, frame.values.count) }
// 原 packets 视图的样本位于 packet.fields["values"]。
```

`sampleRateHz` 和 `expectedSampleCount` 当前为空；接收样本数除以请求时长不作为采样率。样本数、帧数、序号不连续次数与停止状态分别保存。

`interruption` 非空仍可能有可保存的部分数据。前置条件失败、启动失败或取消也可能抛错，不保证所有错误都写在对象内。**分别检查 `stopConfirmed` 与 `interruption`**；双端在无其他中断且停止未确认时标记 `stopUnconfirmed`。保留未确认事实，不因方法返回就认为物理采集结束。

可选模块的通用 `start` / `stop` 与有限录制分别使用。Android 通用 `start` 没有宿主截止定时器，宿主须在 `finally` 调用 `stop()`；有限时长的 ECG 使用 `recordECG`。

## 0.1.9 接口补充

`startCapture(accOnly)` 使用持久会话，只开启 ACC；默认一天、最多七天，支持同身份恢复及导出。`ACCFrame` 含六组有符号 XYZ 原始计数，不提供已校准单位或样本时间。

`readBattery` 是空闲时的单条读取；`chargingStateRaw` 和 `voltage.rawValue` 分别保留 SDK 解码的原始充电码和无符号电压值。充电状态、缩放及单位未经确认，枚举为unknown，物理值和单位为null。采集中仍busy，只有收到实际电量通知时才发电量事件，不保证固件主动推送。

`readWearState` 在00000808-260604上短暂打开PPG/调试，默认观察5秒（另计写入和关闭超时），返回固件接触状态，不留采集目录；忙时busy、无信号unknown、关闭失败stopUnconfirmed并断连。采集中的skinContact事件独立解析完整TOUCH/touch_flag行；未确认语义的设备佩戴事件保留unknown，touch_value阈值未知。未接触时宿主应提示调整佩戴或停止PPG，避免无数据重启循环。旧二进制尚无这些新增接口，升级需重编译并补齐新枚举分支。
