# 采集与马达节拍

SomaLoop 2 SDK 的采集、读取和马达播放共用客户端操作互斥。宿主发起操作、处理事件，并提供可见停止入口。SDK 接受有效 BCD 固件版本 0.0.8.8 及以上，不设版本上限；联合采集、设备校时及内建睡眠/连续心率时间规则仅适用于 `00000808-260604`。

## 采集、停止与导出

Swift 使用 `startCapture(mode:durationSeconds:)`，Kotlin 使用 `startCapture(mode, durationSeconds)`；模式及持久值如下：

| Swift / Kotlin 枚举 | 会话 JSON | serverMode |
| --- | --- | --- |
| ppgOnly | ppg_only | ppgOnly |
| paired | ppg_acc_paired | paired |
| accOnly | acc_only | accOnly |

Android 后台采集通过前台服务接入，见[Android 接入](Android接入.md)。

SDK 会话中的模式序列化为 `ppg_only` / `ppg_acc_paired`。`mode.serverMode` 分别映射为 `ppgOnly` / `paired`；Java 使用 `ApiViews.serverMode(mode)`。宿主上传时明确映射，保留既有会话原文。

启动返回 `CaptureSession`（`SessionManifest` 的同义类型），不保证已经收到有效数据。用 `captureHealth()` 判断 `idle`、`waitingForFirstPacket`、`receiving`、`noData`、`recovering` 或 `stopped`。缺数不自动表示未佩戴，停止状态还要结合 `cleanupPending` 与 `stopConfirmed`。

每段联合采集的首个有效联合帧等待窗口为 15 秒，纯 PPG 为 5 秒；开始出数后持续 5 秒缺数进入恢复判断，软重启后还检查至少 8 秒段运行时间。联合重启段同样保留 15 秒首帧等待。

联合帧 `PairedFrame` 保留 `frameCount`、`timeField`、`ppg` 和 `mems` 等字段。PPG 为原始计数，MEMS 为未校准三轴原始计数。两路数组长度可以不同；SDK 不按索引强配、不补齐、不重采样、不生成逐样本时间。主机接收时间与设备实际采样时间不同。

联合模式以符合配置规则的 `PairedFrame` 判断数据健康与恢复；单独 PPG 通知另行统计，不与联合帧内 PPG 相加。PPG-only 以实际 PPG 通知判断。序号缺口表示相邻接收帧的序号不连续，各模式的统计分别保存。

应用保存操作起止时间和停止状态，同时保留日常历史的原时间轴与质量，参见[操作与日常历史共存](数据与时间语义.md#操作与日常历史共存)。

停止调用 `stopCapture()`，先持久化停止意图。设备离线时保留待清理状态，恢复后仅向与本次会话身份相符的设备尝试关闭，不重新开启已停止的采集。固件、身份变化时不要继续写入旧会话。未请求停止的待处理会话恢复则可能继续采集，宿主需明确其生命周期和用户可见状态。

`exportSession` 返回本地目录快照，`exportDiagnostics` 返回单个诊断 JSON 文件；导出保留原会话，上传由宿主处理。活动会话导出截至快照时刻已持久化的文件前缀，后续采集继续写入原会话。已结束本地采集且 `requested=false`、`cleanupPending=false` 的会话重复导出时，文件内容保持一致；每次导出目录不同。导出保留会话身份、版本、计数、排除原因和停止状态，`checksums.json` 记录各文件的 SHA-256。

`exportSession` 保留原始设备通知，包括设备固件输出的型号、库版本和初始化文本。修改导出内容后需更新校验和。`exportDiagnostics` 提供不含原始通知、任意设备文本或生理值的分享摘要；分享前由宿主检查数据与接收范围。原始 ACC 在 `00000808-260604` 为 `compatibleCandidate`，其他准入固件为 `experimental`；独立实时诊断为 `untested`。

### 停止结果与本地恢复

保留旧 `stopCapture()`，它等待一次停止流程，但返回 Void/Unit 不证明设备已经确认。推荐读取 `stopCaptureWithResult()`；无会话时返回 null。结果字段为 `sessionID`、`outcome`、`attempts`、`reason`、`observedAt`（主机 Unix 秒），以及 `stopConfirmed`、`cleanupPending` 视图；会话文件保留 `stopResult` 和 `stopAttempts`。

| outcome | stopConfirmed | cleanupPending | 应用处理 |
| --- | --- | --- | --- |
| acknowledged | true | false | 设备已回有效停止 ACK，可开始下一项操作 |
| quiescent | false | false | 本地采集结束，可开始下一项操作；记录静默观察结果 |
| unconfirmed | false | true | 保留待清理；自动尝试有上限，展示恢复入口 |
| abandoned | false | false | 用户明确结束本地待处理，设备状态未确认 |

`quiescent` 仅用于 `00000808-260604` 的独立 ACC：本连接实际收到过 ACC，停止写入完成，连接持续就绪，连续 3 秒没有 ACC 数据；停止期间收到任何 ACC 会重新计时。回复等待后最多追加 3 秒观察，持续出帧、断连、无历史出帧或写入失败不会按静默结束。这是本地结束策略，不是设备 ACK；PPG 和联合采集仍按原命令确认。

正常停止流程最多尝试两次，次数先落盘再发命令，应用重启不重置上限。达到上限保留 `unconfirmed`，不再后台重连或循环发送停止。存储或传输致命错误仍执行原有应急关闭写入并断连，应急写入不作为 ACK。用户需要释放本地会话时，提供原因并明确确认：

```swift
if let session = await client.currentSession(), !session.requested, session.cleanupPending {
    // 在应用已经获得用户“结束本地待处理”确认后执行：
    let result = try await client.abandonPendingCapture(
        sessionID: session.id, reason: "用户结束本地待处理会话", confirm: true)
    print(result.outcome)
}
```

```kotlin
val session = client.currentSession()
if (session != null && !session.requested && session.cleanupPending) {
    // 在应用获得用户确认后执行；Java 使用同名 Callback 入口。
    client.abandonPendingCapture(session.id, "用户结束本地待处理会话", true)
}
```

该操作只保存本地结束状态及原因，不发送蓝牙命令，也不宣称设备停机；会话 ID 必须匹配，原因不能为空且 UTF-8 不超过 1024 字节。落盘失败时保留待处理状态。不要把此 API 自动当作停止失败的成功结果。

### 导出目录

| 文件 | 内容 / 出现条件 |
| --- | --- |
| raw-00000.jsonl、raw-00001.jsonl… | 分卷原始收发和生命周期日志，每行一个 JournalRecord |
| session.json | 模式、设备、版本、计数、停止结果与重试次数 |
| paired-frames.jsonl | 接受的联合帧；其他模式可为空 |
| paired-exclusions.jsonl | 联合帧排除原因与快照尾部处理；可为空 |
| stream-events.jsonl | 序号跳变等接收事件；可为空 |
| acc-frames.jsonl | 仅 accOnly，六组 XYZ 与接收日志引用 |
| paired-metadata.json | 解析配置、单位和对齐语义 |
| capture-intent.bin | 单字节，1=仍请求采集，0=停止意图 |
| export.json | 快照时间、记录数及各源文件截取字节数 |
| checksums.json | 导出文件 SHA-256，**不包含自身** |

所有模式保留通用文件，空文件有意义。JSONL 按行读取；`JournalRecord.time`、会话日期固定为 Unix 毫秒，`uptime` 为主机单调秒。快照不会删除原数据，也不表示服务端已接收。

## 马达节拍

支持固件范围内可直接调用 `playHaptics`，不限制固定设备地址、不需要实验开关。保留的 `allowExperimental` 兼容参数不改变该功能准入。它编排开启/关闭时间，不提供机械振幅或机械频率控制。

`HapticPattern.firstPulse` 是两秒示例，可先编译预览，再播放：

```swift
let pattern = HapticPattern.firstPulse
let preview = try pattern.compile(preview: true)
// 连接就绪、App 前台、客户端空闲时播放：
let report = try await client.playHaptics(pattern)
// 另一 Task 可随时停止：await client.stopHaptics()
```

```kotlin
val pattern = HapticPattern.firstPulse
val preview = pattern.compile(preview = true)
// 连接就绪、App 前台、客户端空闲时播放：
val report = client.playHaptics(pattern)
// 另一协程可调用 client.stopHaptics()
```

Java 使用 `playHaptics(pattern, callback)` 和 `stopHaptics(callback)`。名称去除首尾空白后必须非空，原名称长度最多 80 个 UTF-16 代码单元；版本为 1。播放限于前台，实时计划支持 40–120 BPM、4 或 8 拍、单遍、总长不超过 8 秒；短/长开启窗口为 100–500 毫秒，长窗不少于短窗，相邻脉冲关闭间隔至少 100 毫秒。预览支持 40–180 BPM、4/8/16 拍、1–4 遍、总长最多 30 秒，脉冲不重叠；预览参数不能直接用于播放。

调用 `pattern.validationIssues(preview: false)` / `pattern.validationIssues(preview = false)` 可获取带 `code` 和 `message` 的 `HapticValidationIssue` 列表；Java 使用 `validationIssues(false)`。空列表表示该模式的参数校验通过，`compile` 在失败时抛出 `invalidArgument`。应用按 `code` 处理参数错误，并检查播放报告。

取消、后台切换、异常和正常结束均尝试关闭；失联时保存待关闭记录，核对本次持久会话身份后恢复关闭，不自动续播。宿主必须转发真实前后台生命周期。

`playHaptics` 返回本次报告；`currentHaptics` 返回当前客户端的报告，尚未播放时为空。`pendingStop` 表示待关闭/确认状态，`userConfirmedStopped` 必须来自使用者反馈。实际确认停止后调用 `confirmHapticsStopped(sessionID:)` / `confirmHapticsStopped(report.id)`，不能收到回复就自动确认。待关闭未确认时，其他普通操作可能 `stopUnconfirmed`。

SDK通过 `pendingHaptics()` 返回持久待关闭列表，每项含 `sessionID`、原 `device` 和可选 `report`。待关闭按设备保存：同一MAC且固件/日期一致时恢复关闭；同MAC固件或日期改变时仍保留原记录，连接可就绪，相关普通操作继续 `stopUnconfirmed`；其他设备不受该条记录阻挡。

无法继续按原身份关闭，需要结束本地待处理项时，宿主明确确认后调用 `abandonPendingHaptics(sessionID:reason:confirm:)` / `abandonPendingHaptics(sessionID, reason, true)`。原因必须非空；SDK 先保存 `HapticAbandonmentReport` 再移除该项，状态为 `abandoned`，保留原身份、报告和理由。此调用不发送 BLE 命令，也不设置 `userConfirmedStopped`；放弃本地记录与确认马达停止分别处理。

`exportHaptics(sessionID:to:)` / Kotlin `exportHaptics(sessionID, root)` 可按 ID 导出待处理或已放弃的报告；缺原报告时只导出放弃记录。Java 有同名 Callback 重载。无 ID 的导出入口和 `currentHaptics` 保持。

报告的 `completed` 表示本次节拍执行结束。发生 `timingViolation` 或 `linkTooSlow` 时，应用保留中断结果和停止状态。`exportHaptics` 导出本地报告，上传由宿主处理。
