# 恢复出厂与充电唤醒

0.1.16 / build 33 新增公开 `factoryReset` 能力，无需 `allowExperimental`。当前支持固件 **0.0.8.8、构建日期 2026-06-04**；同配置设备为 `compatibleCandidate`，其他固件返回 `unverifiedCapability`。不按固定 MAC 放行。本文描述源码新增接口；发布状态以对应 Release 为准，旧二进制没有这些接口。

## App 操作前说明

建议在用户点击“恢复出厂”时展示以下文案，并在用户确认后执行：

> 请先把已通电的充电底座放在手边，并保存需要保留的数据。
>
> 恢复出厂会使手环暂时无法连接。操作后请将手环从底座取下，再放回底座唤醒；如果手环戴在手上，请取下并放回底座。
>
> 自定义蓝牙名称会恢复为出厂名称，部分设置会恢复，部分历史数据会丢失。调试和系统记录等可能保留，本功能不保证清空所有数据。
>
> 唤醒后，App 需要重新连接并校准时间。完成前，手环新记录的时间可能不准确。

SDK 不展示弹窗，也不替 App 决定数据保存、账号解绑或删除服务端数据。确认一次即可进入该流程；不要把 reset 放在自动连接、重试队列或后台定时任务中。

## App 流程

1. 保存需要的历史和设置，结束正在进行的采集、测量、振动和历史分页。检查 `factoryReset` 能力。
2. 展示上述说明。用户确认后创建准备凭证并立即执行；凭证 30 秒内有效，仅适用于创建它的客户端和当前连接，一次性使用。App 已完成用户确认时，无需为 SDK 凭证另弹一次提示。
3. 请求返回后显示“请放回充电底座唤醒”。`acknowledged` 仅表示收到命令应答，不能显示“全部数据已清空”。超时或断连时显示“操作结果尚未确认，请放回底座后检查”，不重发。
4. 用户放回底座后，重新扫描；广播名称可能已经改变，不要只按旧名称筛选。停止扫描，将候选交给恢复核验接口，由 SDK 读取并比对原 MAC、固件和构建日期。macOS/iOS 的 peripheral UUID 不是 MAC。
5. 核验成功后保留校时前快照，取回需要保留的历史，再显式校时并回读验证。校时失败时显示“已连接，时间尚未校准”，允许稍后继续校时，不再次 reset。
6. 按产品需要重新配置名称和设置。SDK 不自动写回旧名称或旧配置。校时成功后，App 才提示“可以继续使用”。

名称以实际广播为准，不能把 `readDeviceName` 返回的名称字段当作广播名。App 不应承诺固定名称后缀、固定唤醒时长、所有设置恢复或完全清除历史。重新连通本身不证明发生过 reset 或完成了充电唤醒。

## Swift

```swift
// 已完成 App 用户确认；client 当前已连接、空闲且没有未结束的历史分页。
let preparation = try await client.prepareFactoryReset()
// 在调用前保存 preparation.id，便于 App 被终止后查询持久操作记录。
let attempt = try await client.requestFactoryReset(preparation, confirm: true)
// 保存 attempt；废弃旧 checkpoint / 续页游标。提示用户放回充电底座。

// 用户完成唤醒，App 扫描找到候选并停止扫描；不要预先 connect。
let recovery = try await client.verifyFactoryResetRecovery(candidate, attemptID: attempt.id)
// 当前保持连接。recovery.clock 是校时前日历；nameField 不等于广播名。
// 如需保留残留历史，先从头读取并保存原文，再执行校时。
let synchronization = try await client.synchronizeClock(utcOffsetMinutes: 480)
// 核对 synchronization.verified；+480 是本流程明确采用的时区，不是所有历史的时区。
```

## Kotlin 与 Java

```kotlin
val preparation = client.prepareFactoryReset()
val attempt = client.requestFactoryReset(preparation, confirm = true)
// 物理唤醒、扫描并停止扫描后；当前 client 应处于 disconnected。
val recovery = client.verifyFactoryResetRecovery(candidate, attempt.id)
// 保存需要的历史后，显式校时。
val synchronization = client.synchronizeClock(480)
```

Java 包装器提供 `prepareFactoryReset(callback)`、`requestFactoryReset(preparation, true, callback)`、`verifyFactoryResetRecovery(candidate, attemptID, callback)`、`readFactoryResetAttempt(id, callback)`、`lastFactoryResetAttempt(callback)`，结果类型分别与 Kotlin 相同。取消 Java 任务可能不再收到回调；按已保存的准备凭证 ID 查询操作记录，不能因没有回调而重新发送。

## 状态、持久化与异常

`FactoryResetAttempt` 包含操作 ID、设备身份、请求前时钟、Unix 秒时间、独立 `clockEpoch`、上一次写钟 epoch、状态、原始 ACK、错误和可选恢复报告。状态含义如下：

| 状态 | 含义与处理 |
| --- | --- |
| `intent` | 发送前已持久化意图；进程中断后不能确定帧是否送达。按可能已执行处理，先唤醒核验 |
| `acknowledged` | 收到严格匹配的应答；仍需要物理唤醒、身份核验及校时 |
| `indeterminate` | 写入、等待应答、取消或连接阶段发生异常，效果未知；禁止自动重发 |

`checkpointResetRequired` 对已持久化的尝试始终为 true。`requiresChargingWake` 在没有成功恢复报告时为 true，是流程提示，不是对设备当前电源状态的实时测量。

SDK 在 `storageRoot/factory-reset-events.jsonl` 中同步保存操作观察，不保存可自动执行的任务。App 重启后复用原 `storageRoot`，使用 `readFactoryResetAttempt(id:)` / Kotlin `readFactoryResetAttempt(id)` 查询。`lastFactoryResetAttempt` 是当前已识别设备的缓存；新客户端尚未连接时应按 ID 查询。保留日志，不通过删除它解除待核验状态。更换根目录或卸载 App 会失去本地记录，SDK 不提供跨安装的全局去重保证。

没有持久记录且前置检查明确失败时，尚未进入 reset 提交阶段。存储损坏或读取失败不能解释为“设备未重置”。写入后的报告保存失败仍可能已经改变设备；保留发送前的 `intent`，按不确定结果处理。

恢复核验要求客户端处于 `disconnected`，并使用该设备最新的操作 ID。它自己建立新连接、验证身份，读取设备时钟、名称字段以及 basic、personalInfo、reminders、automaticMeasurement(type 1/2/4) 共六组设置。全部成功才持久保存 `FactoryResetRecovery`；它不执行全历史清除验证、不校时，两个相应布尔字段始终为 false。失败时断开连接，可以稍后重试此只读核验。

已有待恢复记录时不允许准备另一次 reset。发送阶段至多提交一次，不自动重连。取消不能撤销已发出的命令。`shutdown()` 等待当前 reset 操作完成记录与清理后再释放目录。SDK 请求断开自身连接，不把它记录为设备自行断链的证据。

## 时间与历史

reset 意图持久化时立即建立新的 `currentClockEpoch`，即使 ACK 不确定也如此。`lastClockWriteEpoch` 继续只表示真正的写钟尝试；不能伪造一次校时。后续显式校时又会产生新的写钟 epoch。

App 必须保留原记录，废弃旧 checkpoint、分页游标和同步进度，从头对账。不能因为记录在 reset 后读到，就把残留旧记录全部当作 reset 后新采集的数据。SDK 不将已有历史平移到新时间，也不凭当前校时修正历史中的异常年份。

存在 reset 记录时，普通连接的 `connectionClockSync` 会暂缓自动写钟，直到恢复核验完成且另行发生显式写钟尝试。恢复核验自身始终只读。校时尝试不等于成功，App 仍须检查回读结果；失败保持“时间未校准”。

## 效果与验证范围

2026-10-10 在一台 0.0.8.8 / 2026-06-04 设备上的本地 macOS 实验观察到：广播名称恢复；部分业务历史读空；大量调试和系统历史保留；部分自动测量间隔改变；重置与充电唤醒之间时钟不连续，之后正常走时但保留偏差；随后佩戴能产生新的心率记录。未复现 2036 年，未证明问题反馈中的原厂 App 完整操作序列。

这支持公开接口的有限契约，不构成全数据擦除、其他固件、手机后台、解绑安全或医学验证。历史按类型清除仍见[历史清除](历史清除.md)。reset 不保证删除配对密钥或阻止旧手机继续访问。

新 API 的本地测试与构建状态见[验收状态](验收状态.md)；此前物理实验使用本地工具，不能冒充本次新 API 或正式 iOS/Android 二进制的真机验证。
